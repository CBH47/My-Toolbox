### Change 4: Add I2C pre-initialization scan before display init (in `setup()`, lines ~825-826)

Before calling `initDisplays()`, add an I2C scan on both buses to verify device presence at address 0x3C:

```cpp
// Pre-init I2C scan for OLED A (Bus 0)
Serial.print("Scanning I2C Bus 0 (OLED A)... ");
I2CBus1.begin(OLED1_SDA, OLED1_SCL);
bool oledAFound = false;
Wire.beginTransmission(0x3C);
if (Wire.endTransmission() == 0) {
    Serial.println("Device found at 0x3C");
    oledAFound = true;
} else {
    Serial.println("No device at 0x3C on Bus 0");
}

// Pre-init I2C scan for OLED B (Bus 1)
Serial.print("Scanning I2C Bus 1 (OLED B)... ");
I2CBus2.begin(OLED2_SDA, OLED2_SCL);
bool oledBFound = false;
Wire.beginTransmission(0x3C);
if (Wire.endTransmission() == 0) {
    Serial.println("Device found at 0x3C");
    oledBFound = true;
} else {
    Serial.println("No device at 0x3C on Bus 1");
}

// Then call initDisplays() as normal
Serial.println("[1/5] Initializing displays...");
initDisplays();
```

Note: The I2C scan in `display.cpp` (`initDisplays`) already calls `I2CBus1.begin()` and `I2CBus2.begin()`. To avoid duplicate begin calls, either:
- Option A: Remove the `begin()` calls from `initDisplays()` in display.cpp since they're called during scan
- Option B: Use a separate Wire instance for scanning (but this is more complex)

Recommend Option A: In `display.cpp` `initDisplays()`, remove or guard the `I2CBus1.begin()` and `I2CBus2.begin()` calls, since they are now called before `initDisplays()` during the scan phase. The `beginTransmission/endTransmission` scan already initializes the buses.
